# /codify — 知识沉淀技能

把会话中散落的调研结论、踩坑记录、新发现，提炼为结构化 md 文档落盘。

## 触发方式

- `/codify` — 自动提炼当前上下文，存到工作目录
- `/codify <path>` 或 "沉淀到 X" — 指定子目录（如 `asksurf`）
- "沉淀" — 等价于 `/codify`

## 工作流

### Step 1：扫描已有文档，优先找插入位置

先 Glob/Read 当前工作目录（及用户指定子目录）下已有的 `.md` 文件，判断本次内容是否应**并入现有文档**，而不是默认新建。

**优先插入已有文档**，当内容满足任一条件：

- 与某篇文档的主题、机器、组件、流程明显同一脉络（如 Devbox 清单、某台机器配置、某次 debug 的续篇）
- 是对已有章节的事实更新、状态变更、补充踩坑（如 alias 变更、代理接入范围调整）
- 工作区已有约定入口（如 `AGENTS.md` 指向的 source-of-truth 文件）

**再新建文件**，仅当：

- 扫描后没有主题匹配的现有文档
- 内容体量或生命周期独立，硬塞进现有文档会污染结构（如全新子项目、完全无关的专题）
- 用户显式指定新路径或新文件名

用户显式指定目标时（`/codify <path>`、"沉淀到 X/file.md"），以用户指定为准，但仍可先建议更合适的已有文档。

### Step 2：确定写入目标

| 用户输入 | 默认行为 |
|---------|---------|
| `/codify` | 先 Step 1 匹配已有文档；无合适落点则 `<cwd>/codify-<topic>.md` |
| `/codify <path>` | `<cwd>/<path>/README.md`（目录）或按路径解析 |
| "沉淀到 X" | `<cwd>/X/README.md` |
| "沉淀到 X/file.md" | `<cwd>/X/file.md`（用户指定完整文件名） |

### Step 3：判断内容性质与格式

在**已选定的目标文档**内，根据**会话内容的性质**决定段落结构；若并入已有文档，须对齐该文档既有标题层级与行文风格。

不使用固定模板。以下是性质→格式的参考（不是规则，自行判断）：

- 产品调研 → 可能适合：定位/功能/商业模式/竞品对比
- 技术方案 → 可能适合：问题/方案/取舍/实现细节
- Debug 记录 → 可能适合：现象/排查过程/根因/修复
- 对比分析 → 可能适合：表格为主，维度对比
- 读书/论文笔记 → 可能适合：核心论点/关键证据/个人思考

原则：**内容决定形式，不是形式框住内容**。只写有价值的，不凑章节。

### Step 4：写入文件

- **已有文档**：Read 全文后，用 Edit 在合适章节下插入或更新对应段落；不覆盖无关内容，不重复已有结论
- **新建文档**：用 Write 创建；若目标文件已存在，Read 后追加/更新，不整篇覆盖
- 写完告知用户**实际写入的文件路径**；若是并入已有文档，简要说明插入在哪个章节

## 规则

- **优先更新已有 docs，其次新建**；避免同一工作区平行维护多份重复 inventory / 配置记录
- **默认存当前工作目录**，不存 `~/.claude/` memory 系统
- 文档语言跟随会话语言（中文会话写中文，英文写英文）
- 代码块、URL、专有名词保持原文
- 不添加 emoji
